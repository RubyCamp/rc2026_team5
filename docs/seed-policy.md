# seed・初期化・復旧方針

## 方針

- `find_or_initialize_by`を使い、再実行しても重複しない
- 固定日付と架空の教材用データを使う
- 共通DBで全件削除や破壊的seedを前提にしない
- 正常系に加え、人数不足、勤務不可、スキル不足、重複時間帯の代表ケースを画面で確認できるようにする
- ChangeEventには未確認と確認済みの表示見本を含める

## 基準件数（空DB）

- スタッフ：4名
- 事業者：2件
- スキル：2件
- 勤務依頼：5件
- 勤務割当：4件
- 変更記録：5件

既存の共通DBにはチームが登録したデータもあるため、DB全体の件数がこの値と一致するとは限らない。基準データは名称・コードで識別する。

## 再構築

ローカルDBを基本状態へ戻す場合だけ、接続先がローカルであることを確認してから次を実行する。

```sh
bin/rails db:drop db:create db:migrate db:seed
```
